# 03-health-affiliate-blog

## 목표

독자의 생활 속 불편에서 출발해 확인할 기준과 오늘 할 수 있는 행동을 알려 주는 건강 글을 작성한다. 질병을 단정하거나 치료·약 복용·구매를 유도하지 않는다.

글의 제목·문체·설득 구조와 제품 연결 방식은 `02-naver-shopping-connect-blog`를 함께 적용한다. 건강 안전·이미지 생성·네이버 임시저장 규칙은 이 스킬을 우선하고, 정보형 흐름과 제품 노출 위치는 02 스킬을 따른다. 본문에는 특정 상품명·브랜드명·모델명·가격·판매처를 쓰지 않으며, 제품군의 기능과 선택 기준만 생활 언어로 설명한다. 실제 상품 카드는 마지막 CTA 뒤에 시스템이 추가하고, 원시 URL이나 네이버가 자동 적용하는 대가성 고지를 본문에 중복 입력하지 않는다.

## 글쓰기 기준

### 사람말투 기본값

- 블로그 운영자가 독자에게 직접 설명하듯 쉬운 존댓말로 쓴다. 기사 요약체, AI식 해석, 교훈적인 마무리를 기본 문체로 삼지 않는다.
- 사실과 실천법을 필요한 만큼만 말한다. 문단마다 의미·평가를 덧붙이거나 같은 내용을 표현만 바꿔 반복하지 않는다.
- `눈길을 끕니다`, `인상적입니다`, `참고할 만합니다`, `필요는 없겠죠`, `생각이 들었습니다` 같은 상투어를 문단 마감용으로 쓰지 않는다.
- `단순히 A가 아니라 B`, `A로만 보기보다 B에 주목`, `그 과정이 중요합니다` 같은 AI식 해석 문장틀을 반복하지 않는다.
- `~했는데요`만 이어 쓰지 않고 짧은 평서형과 설명형을 섞는다. 정보가 부족하면 분량을 억지로 늘리지 않는다.
- 건강상 꼭 필요한 개인차·금기·진료 기준은 생략하지 않는다. 다만 `사람마다 다를 수 있어요`라는 막연한 면책으로 끝내지 말고, 누구에게 어떤 조건이 해당하는지 구체적으로 쓴다.

- 공식 기관·의료기관·학회 자료를 우선 확인하고, 기사 문장을 복사하지 않는다.
- 글감 후보 제목은 `증상 또는 생활 고민 + 자연스러운 질문 + 확인 기준`으로 새로 쓰고, 뉴스·블로그 원문 제목을 그대로 복사하거나 어미·문장부호만 바꿔 사용하지 않는다.
- 사용자가 글감을 선택한 뒤에는 그 글감 제목을 최종 포스팅 제목으로 고정한다. 본문 작성 과정에서 검색 키워드·어미·숫자·문장부호를 고치거나 새 제목으로 바꾸지 않는다. 네이버 임시저장 제목, 대표이미지 기준 제목, 이미지 다운로드 폴더 이름도 모두 선택한 글감 제목과 정확히 같게 유지한다.
- 본문은 1,300자 이상, 문단은 1~2문장으로 쓴다. 같은 설명을 반복해 분량을 채우지 않는다.
- 첫 1~2개 짧은 문단은 독자가 겪는 구체적인 시간·장소·행동과 불편으로 시작한다. 이어지는 문단에서 질문에 직접 답하고, 서론 전체 2~4문단 안에 생활에서 확인할 기준을 안내한다. `먼저 답하면`, `결론부터 말하면` 같은 기계적인 시작 문구는 쓰지 않는다.
- `이 글에서 확인할 핵심 N가지` 같은 보고서식 요약과 번호 목록을 습관적으로 만들지 않는다. 제목이 숫자를 약속한 경우에만 본문에서 그 수만큼 실제 내용을 설명한다.
- 증상이나 몸의 변화를 검색하는 글은 반드시 `문제 제기 → 나타나는 증상과 확인 기준 → 가능한 원인과 악화 요인 → 해결 방법 및 생활 대책 → 진료가 필요한 위험 신호` 순서로 전개한다. 각 단계는 앞 단계의 내용을 되풀이하지 않고 다음 질문에 답해야 한다.
- 증상 구간에서는 독자가 자기 상태와 비교할 수 있는 양상·시간·동반 변화를 설명하고, 원인 구간에서는 흔한 가능성과 생활 요인을 구분한다. 증상만으로 특정 질환을 단정하거나 원인을 하나로 확정하지 않는다.
- 해결 방법 및 대책 구간은 비용 없이 할 수 있는 행동을 먼저 제시하고, 기대할 수 있는 변화와 멈춰야 할 기준을 함께 쓴다. 제품은 이 행동을 돕는 보조 수단일 때만 뒤에서 연결한다.
- 식재료·운동·수면처럼 증상 중심이 아닌 주제도 `생활 문제 → 현재 상태 확인 → 영향을 주는 요인 → 실천 대책 → 주의할 사람`의 같은 논리 순서를 유지한다.
- 본문은 자료를 바탕으로 한 자연스러운 정보성 설명으로 쓴다. 기관명·연도·출처를 보고서처럼 억지로 끼워 넣어 독자의 흐름을 끊지 않는다.
- 약을 줄이거나 중단하라고 말하지 않는다. 증상만으로 진단하지 않으며, 응급 신호는 진료 필요성을 분명히 쓴다.
- 마지막 CTA는 오늘 할 행동을 제안하는 2~3문장으로 쓴다. 구매를 강요하지 않는다.
- 오늘 할 행동에는 주제에 맞는 음식·식사 구성·생활습관·가벼운 운동을 먼저 넣는다. 기록·메모·수첩·며칠 적어 보기는 증상의 시간·횟수·변화가 판단이나 진료 상담에 실제로 필요한 주제에서만 제안한다. 단순 식사·음료 온도·운동·옷차림·휴식 주제에는 기록을 습관적으로 넣지 않는다.
- 제품은 실천을 더 편하게 만드는 보조 수단으로만 연결한다. 영양제품은 관련 음식과 식사 구성을 먼저 설명하고 식사만으로 매일 챙기기 어려운 상황에서 보완 선택지로 연결한다. 생활도구는 제품 없이 해보는 과정에서 생기는 준비·세척·휴대·보관의 번거로움을 먼저 설명한다. `이런 실천을 더 편하게 이어 가는 제품도 있습니다` 같은 고정 문장을 반복하지 않는다.
- 제품을 연결하기 전에는 생활관리 뒤에도 남는 구체적인 불편과 제품 없이 해볼 방법을 설명한다. 비타민·영양제·건강식품이면 관련 음식과 실제 식사 예시를 먼저 제시하고, 생활도구라면 반복되는 준비·세척·휴대·보관의 번거로움을 짚는다. 특정 상품명은 쓰지 않고 제품군의 쓰임으로만 연결한다.
- 제품 선택 소제목은 특정 제품명이나 제품군을 앞세우지 않고 앞의 생활 행동을 자연스럽게 이어받는다.
- 실제 생활에서 독자가 겪을 법한 장면을 한 번은 넣어 설명한다. 다만 직접 사용하거나 겪은 것처럼 꾸미는 가짜 후기는 쓰지 않는다.
- 제품이 주제의 행동과 자연스럽게 연결될 때만 선택 기준 구간을 사용한다. 특정 상품을 소개하지 않고 크기·구조·사용 편의·관리 방법 같은 기준이 어떤 불편과 관계있는지를 짧은 생활 문단으로 설명한다. 제품 연결이 억지스러우면 별도 제품 구간을 만들지 않는다.
- 제품 구간은 해결 방법 바로 뒤, 진료·응급 신호보다 앞에 둔다. 진료 기준 뒤에는 새 제품 설명을 시작하지 않으며 글의 마지막 정보 구간은 진료 기준으로 마무리한다.
- 실제 상품 상세정보는 제품군의 일반적인 기능과 선택 기준을 정하는 내부 참고로만 사용한다. 본문에는 상품명·브랜드명·모델명·가격·판매처를 쓰지 않으며 확인되지 않은 기능·소재·효과를 만들지 않는다.
- 사용자가 특정 제휴상품을 지정해도 본문에서는 특정 상품을 소개하지 않는다. 마지막 CTA는 앞서 설명한 기준으로 사용할 제품을 찾고 있다면 아래에 골라둔 선택지를 천천히 비교해 보라는 1~2문장으로 마무리한다. 실제 상품은 CTA 뒤의 상품 카드에서만 보이게 한다.
- 추천 제품은 글의 핵심 생활 장면에서 독자가 실제로 사용할 수 있는 비처방 상품군으로 고른다. 기록 노트·건강 수첩·증상 일지·다이어리는 제품 후보와 제품 선택 소제목에서 제외한다. 증상 기록이 꼭 필요하면 휴대전화 메모처럼 별도 구매가 필요 없는 방법을 본문에서 짧게 안내한다. 예: 음료 온도 조절→디지털 음료 온도계, 식단 준비→전자 주방저울·밀폐 소분용기, 수면 환경→차광 수면안대, 장 건강 식사→무가당 플레인 요거트, 혈변·치질 생활관리→변기 설치형 좌욕기, 자세 관리→허리 쿠션, 아이 음식 알레르기 전달→방수 식품 알레르기 표시 스티커.
- 처방약·일반의약품·치료 효과를 내세운 제품은 추천하지 않는다. 혈압계·알코올 측정기처럼 판단에 영향을 줄 수 있는 도구는 의료진 안내·법적 안전 기준을 대신하지 않는다고 함께 밝힌다.
- 해시태그는 핵심 키워드·문제 상황·생활관리·제품군을 섞어 5~10개로 만든다. 게시 설정용 별도 항목으로 관리하고 본문 마지막 CTA 뒤에 텍스트로 붙이지 않는다.
- 네이버 블로그에 임시저장할 때 모든 `heading` 소제목은 일반 본문이나 글자 크기 변경 방식이 아니라 스마트에디터의 `인용구2` 서식으로 입력한다. 소제목 다음 본문은 인용구 밖의 일반 문단으로 이어 쓴다.

## 원고 생성과 빠른 확인

- 건강 원고는 AI로 한 번만 작성한다. 별도의 AI 자체 검수나 두 번째 전체 재작성 호출을 하지 않는다.
- 작성 뒤에는 코드로 빠르게 확인할 수 있는 필수 항목만 검사한다: 정상적인 제목·본문, 이미지 자리 4~6개, 해시태그 5~10개, 제휴 추천에 의약품·복용 유도 표현이 없는지.
- 분량·문체·정보 흐름·CTA 같은 글쓰기 기준은 첫 작성 지침으로 유지하되, 이 권장 기준 때문에 원고 전체를 다시 생성하거나 작업을 중단하지 않는다.
- 첫 결과를 내기 전에 같은 증상 설명·생활관리·진료 권고·제품 필요성·결론이 반복되는지 한 번 확인해 합친다. 이 과정은 별도 AI 재작성 호출을 만들지 않는다.
- 필수 형식 또는 건강 안전 항목에 문제가 있을 때만 저장을 중단하고 해당 문제를 알린다.

## 이미지 자리

본문에 4~6개의 `image` 블록을 넣는다. 각 블록에는 순서(`slot`), 짧은 위치 제목(`caption`), 구체적인 장면 설명(`desc`)을 둔다. 대표 장면, 생활 문제 장면, 주제에 필요한 확인 장면, 실천 장면이 겹치지 않게 구성한다. 기록 장면은 기록이 실제 판단에 필요한 글에서만 사용한다.

- 대표이미지는 글 맨 위에 둔다. 본문 첫 번째 이미지(`slot 1`)는 도입 2~4문단이 끝난 뒤 첫 정보 구간에 배치한다.
- `caption`은 내부 장면 식별과 파일명에만 사용한다. 네이버 이미지 아래 `사진 설명`에는 caption, `(AI 연출 이미지)`, `(생성 이미지)` 등 어떤 문구도 입력하지 않고 빈 상태로 둔다.
- 네이버에 올린 대표이미지와 AI로 생성한 모든 본문 이미지는 이미지별 `AI 활용 설정`을 켠다. 이미 켜져 있으면 다시 누르지 않으며, 2차 임시저장 후 모든 이미지가 켜졌는지 확인한다.

## 대표이미지

- 본문 이미지 4~6장과 별도로 대표이미지 1장을 추가한다.
- 대표이미지는 항상 `1080×1080px` 정사각형, 화면 비율 `1:1`로 만든다.
- 대표이미지는 글 제목의 핵심 검색어를 큰 글자로 넣고, 독자가 얻을 내용을 나타내는 관련 문구를 짧게 덧붙인다.
- 핵심 키워드는 1개만 사용한다. 관련 문구는 한 줄 또는 두 줄, 8~18자 정도로 쓰고 과장·공포·치료 보장·구매 유도 표현을 피한다.
- 예: 핵심 키워드 `혈당스파이크`, 관련 문구 `오전 허기 줄이는 아침 식사 기준`.
- 한글이 깨지는 것을 막기 위해 이미지 생성 모델에 문구 렌더링을 맡기지 않는다. 먼저 문구가 들어갈 여백이 있는 관련 배경을 생성한 뒤, 로컬 이미지 편집으로 확정된 한글 문구를 정확히 입힌다.
- 대표이미지만 글자를 허용한다. 본문 이미지는 계속 텍스트·로고·워터마크 없이 생성한다.
- 파일명은 `00-대표이미지-핵심키워드.png`로 저장한다. 본문 이미지 파일 번호는 `01`부터 시작한다.

## 실행 순서

Codex가 글감 선택부터 직접 진행할 때는 글 하나를 아래 순서로 모두 끝낸 뒤에만 다음 글로 넘어간다.

1. 건강 글감 하나를 고르고 공식 자료를 조사한다.
2. 글과 이미지 자리 4~6개를 작성한다.
3. 네이버 블로그에 **1차 임시저장**한다. 발행하지 않는다.
4. 임시저장 성공과 제목을 확인한다.
5. 글의 핵심 키워드와 관련 문구를 정하고, 문구가 정확히 들어간 대표이미지 1장을 만든다.
6. 이미지 자리 순서에 맞는 본문 이미지 4~6장을 생성한다. 본문 이미지에는 텍스트·로고·워터마크·약품 포장·의료 진단 장면을 넣지 않는다.
7. 이미지를 `%USERPROFILE%\Downloads\건강블로그이미지\YYYY-MM-DD-글제목\`에 `00-대표이미지-핵심키워드.png`, `01-본문장면.png` 순서로 저장한다.
8. 대표이미지를 포함해 파일이 실제로 5~7장 존재하는지 확인한다.
9. 방금 1차 임시저장한 제목과 정확히 일치하는 최신 임시글을 다시 연다. 제목이 일치하지 않으면 본문을 지우지 말고 중단한다.
10. `이미지 N 넣을 자리`와 `추천 장면:` 안내를 제거한다. 대표이미지는 글 맨 위에 두고, 본문 첫 이미지는 도입 뒤에 둔 다음 나머지 이미지를 `slot` 순서에 맞는 위치에 넣는다.
11. 모든 생성 이미지의 `AI 활용 설정`을 켜고 사진 설명 입력란은 비워 둔다. 실제 쇼핑커넥트 상품이 있으면 CTA 뒤에 에디터의 `쇼핑커넥트` 버튼으로 발급한 상품 카드를 추가하고, 해시태그 5~10개는 에디터의 태그 설정에 입력한다. 대표이미지 1장과 본문 이미지 4~6장이 모두 보이고 안내 문구가 남지 않았는지 확인한 뒤 **2차 임시저장**한다.
12. 저장 목록에서 같은 제목의 글을 다시 열어 이미지 수와 안내 문구 제거를 재확인한다. 새 임시글을 하나 더 만들지 않고 기존 1차 임시글을 갱신한다.

여기까지가 완료 기준이다. 제목 확인, 이미지 전체 배치, 안내 문구 제거, 2차 임시저장 확인 중 하나라도 실패하면 1차 임시글과 로컬 이미지는 그대로 보존하고 실패한 배치 단계만 재시도한다.

## 이미지 생성·배치 완료 규칙

- 1차 임시저장 뒤 `imageCount: 0` 또는 `imagesPending: true`인 글은 아직 완료가 아니다.
- Codex는 사용자가 따로 “이미지를 만들어”라고 다시 말하지 않아도, 같은 글의 대표이미지 1장과 본문 이미지 4~6장을 바로 생성하고 저장한다.
- **1차 임시저장은 작업 종료 지점이 아니다.** 임시저장 성공을 확인한 즉시 같은 작업 안에서 이미지 생성·로컬 저장·네이버 배치·2차 임시저장을 연속 실행한다. 어느 단계라도 남아 있으면 사용자에게 완료 답변을 보내거나 다음 요청을 기다리지 않는다.
- 글 하나를 처리하는 동안 그 글의 제목과 이미지 자리 정보를 작업 대상으로 고정한다. 이미지 저장과 상태 갱신이 끝나기 전에는 다른 글을 시작하지 않는다.
- 생성에는 Codex 기본 이미지 생성 기능을 사용한다. API 키를 요구하거나 ZIP 파일을 만들지 않는다.
- 파일은 글마다 별도 폴더에 저장한다. 대표이미지는 `00-...png`, 본문 이미지는 `01-...png`부터 이미지 자리 `slot` 순서와 동일하게 이름을 붙인다.
- `imageSlotCount`는 본문 이미지 자리 수 4~6개를 뜻하고, `imageCount`는 대표이미지를 포함한 실제 저장 파일 수 5~7개로 기록한다.
- 저장 뒤 파일 개수와 파일 크기를 확인하고, 작업 데이터의 `imageCount`, `imagesPending: false`, `imageDownloadDir`을 갱신한다.
- 네이버 배치가 끝나면 `imagePlacementCompleted: true`, `secondDraftSaved: true`, `insertedImageCount: imageCount`를 기록한다.
- 완료 보고에는 반드시 글 제목, 실제 저장 폴더 링크, 생성·배치한 이미지 장수, 2차 임시저장 확인 결과를 포함한다. 이미지 생성·저장·배치 확인 전에는 완료라고 보고하지 않는다.
- 여러 글을 요청받아도 한 글의 `글 작성 → 1차 임시저장 → 이미지 생성·로컬 저장 → 같은 임시글에 배치 → 2차 임시저장`을 끝낸 다음 다음 글로 넘어간다.

### 완료 직전 필수 검사

아래 여섯 조건이 모두 참일 때만 글 1개를 완료로 보고한다.

1. 네이버 임시저장이 성공했다.
2. `imageSlotCount`가 4~6이고, `imageCount`가 `imageSlotCount + 1`이며, `imagesPending`이 `false`다.
3. `imageDownloadDir`의 실제 이미지 파일 수가 `imageCount`와 같고 모든 파일 크기가 0보다 크다.
4. 대표이미지 파일명이 `00`부터 시작하고 `1080×1080px` 정사각형이며 핵심 키워드·관련 문구가 정확히 보인다. 본문 이미지 파일명은 `01`부터 시작해 이미지 자리 순서와 일치한다.
5. 같은 제목의 1차 임시글을 다시 열어 대표이미지는 맨 위, 본문 첫 이미지는 도입 뒤, 나머지는 각 `slot` 위치에 배치했고 `insertedImageCount`가 `imageCount`와 같다.
6. 모든 이미지의 `AI 활용 설정`이 켜져 있고 사진 설명이 비어 있으며, 이미지 자리·추천 장면 문구가 남아 있지 않고 `imagePlacementCompleted: true`, `secondDraftSaved: true`로 저장 목록 재확인까지 통과했다. 실제 상품 글은 CTA 아래에 해당 쇼핑커넥트 카드가 있고, 해시태그 5~10개가 에디터 태그 설정에 있으며 원시 URL·본문 출처 목록·중복 고지가 없어야 한다.

하나라도 거짓이면 완료 보고 대신 누락된 이미지 생성·복사·상태 갱신부터 계속한다.
