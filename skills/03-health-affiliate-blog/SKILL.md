# 03-health-affiliate-blog

## 티스토리 본문 제외 규칙

- 서론 뒤에 `이 글에서 확인할 핵심 N가지` 요약 목록을 넣지 않는다. 발행 단계의 목차가 글의 흐름을 대신 보여 준다.
- 본문에는 제휴상품명, 제품 소개 소제목, 제품 구매·선택 기준, 번호형 구매 체크리스트, 판매 페이지 CTA를 넣지 않는다.
- 브랜드커넥트 고지는 본문 최상단에, 실제 상품 링크는 본문과 분리된 글 맨 마지막 영역에 발행기가 자동으로 넣는다.

## 목표

독자의 생활 속 불편에서 출발해 확인할 기준과 오늘 할 수 있는 행동을 알려 주는 건강 글을 작성한다. 질병을 단정하거나 치료·약 복용·구매를 유도하지 않는다.

글의 설득 구조와 제품 연결 방식은 `11-health-shopping-connect-blog`를 함께 적용한다. 건강 안전·이미지 생성·티스토리 저장 규칙은 이 스킬을 우선하고, 글의 순서·생활 공감·제품 필요성·선택 기준·비교 CTA는 11 스킬을 따른다. 실제 상품과 링크가 없으면 `제품 후보:`까지만 쓰고, 실제 상품 정보가 있을 때만 쇼핑커넥트 고지와 링크 CTA를 사용한다.

## 글쓰기 기준

- 공식 기관·의료기관·학회 자료를 우선 확인하고, 기사 문장을 복사하지 않는다.
- 글감 후보 제목은 투데이 건강의 기존 검색형 문체에 맞춰 `핵심 키워드 + 효능·증상·원인·관리방법·먹는방법·주의사항 중 실제 답하는 범위`로 짧게 새로 쓰고, 뉴스·블로그 원문 제목을 그대로 복사하거나 어미·문장부호만 바꿔 사용하지 않는다.
- 사용자가 글감을 선택한 뒤에는 그 글감 제목을 최종 포스팅 제목으로 고정한다. 본문 작성 과정에서 검색 키워드·어미·숫자·문장부호를 고치거나 새 제목으로 바꾸지 않는다. 티스토리 저장 제목, 대표이미지 기준 제목, 이미지 다운로드 폴더 이름도 모두 선택한 글감 제목과 정확히 같게 유지한다.
- 본문은 보통 1,500~2,200자, 문단은 1~3문장으로 쓰되 글자 수를 채우려고 반복하지 않는다. 검색자의 질문에 충분히 답하는 것을 분량보다 우선한다.
- 첫 1~2개 짧은 문단은 독자가 겪는 구체적인 시간·장소·행동과 불편으로 시작한다. 이어지는 문단에서 질문에 직접 답하고, 서론 전체 2~4문단 안에 생활에서 확인할 기준을 안내한다. `먼저 답하면`, `결론부터 말하면` 같은 기계적인 시작 문구는 쓰지 않는다.
- 서론 바로 뒤에는 기본적으로 `이 글에서 확인할 핵심 3가지`를 굵게 쓰고 번호 목록으로 요약한다. 제목에 다른 숫자가 있거나 응급 안전상 기준이 더 필요할 때만 4~5가지로 조정하며, 제목과 판단 기준의 숫자를 맞춘다.
- 증상이나 몸의 변화를 검색하는 글은 반드시 `문제 제기 → 나타나는 증상과 확인 기준 → 가능한 원인과 악화 요인 → 해결 방법 및 생활 대책 → 진료가 필요한 위험 신호` 순서로 전개한다. 각 단계는 앞 단계의 내용을 되풀이하지 않고 다음 질문에 답해야 한다.
- 증상 구간에서는 독자가 자기 상태와 비교할 수 있는 양상·시간·동반 변화를 설명하고, 원인 구간에서는 흔한 가능성과 생활 요인을 구분한다. 증상만으로 특정 질환을 단정하거나 원인을 하나로 확정하지 않는다.
- 해결 방법 및 대책 구간은 비용 없이 할 수 있는 행동을 먼저 제시하고, 기대할 수 있는 변화와 멈춰야 할 기준을 함께 쓴다. 제품은 이 행동을 돕는 보조 수단일 때만 뒤에서 연결한다.
- 식재료·운동·수면처럼 증상 중심이 아닌 주제도 `생활 문제 → 현재 상태 확인 → 영향을 주는 요인 → 실천 대책 → 주의할 사람`의 같은 논리 순서를 유지한다.
- 본문은 자료를 바탕으로 한 자연스러운 정보성 설명으로 쓴다. 기관명·연도·출처를 보고서처럼 억지로 끼워 넣어 독자의 흐름을 끊지 않는다.
- 약을 줄이거나 중단하라고 말하지 않는다. 증상만으로 진단하지 않으며, 응급 신호는 진료 필요성을 분명히 쓴다.
- 마지막 CTA는 오늘 할 행동을 제안하는 2~3문장으로 쓴다. 구매를 강요하지 않는다.
- 오늘 할 행동에는 주제에 맞는 음식·식사 구성·생활습관·가벼운 운동을 먼저 넣는다. 기록·메모·수첩·며칠 적어 보기는 증상의 시간·횟수·변화가 판단이나 진료 상담에 실제로 필요한 주제에서만 제안한다. 단순 식사·음료 온도·운동·옷차림·휴식 주제에는 기록을 습관적으로 넣지 않는다.
- 제품은 실천을 더 편하게 만드는 보조 수단으로만 연결한다. 영양제품은 관련 음식과 식사 구성을 먼저 설명하고 식사만으로 매일 챙기기 어려운 상황에서 보완 선택지로 연결한다. 생활도구는 제품 없이 해보는 과정에서 생기는 준비·세척·휴대·보관의 번거로움을 먼저 설명한다. `이런 실천을 더 편하게 이어 가는 제품도 있습니다` 같은 고정 문장을 반복하지 않는다.
- 제품을 연결하기 직전에는 두 단계의 다리 문장을 둔다. 첫 문단은 제품명을 쓰지 않고 생활관리 뒤에도 남는 구체적인 불편과 제품 없이 해볼 방법을 설명한다. 다음 문단은 제품 종류에 맞게 쓴다. 비타민·영양제·건강식품이면 `이럴 때 식사에서 함께 챙겨볼 영양소로 비타민B군을 살펴볼 수 있습니다`처럼 현재 생활 문제와 영양소를 먼저 잇는다. 이어 관련 영양소가 들어 있는 음식과 실제 식사 예시를 제시하고, 식사를 꾸준히 준비하기 어려운 생활 장면에서 제품명을 처음 소개한다. 영양성분·섭취량 같은 구매 기준으로 제품 문단을 갑자기 시작하지 않는다. 생활도구는 반복되는 준비·세척·휴대·보관의 번거로움을 짚은 뒤 연결한다.
- 제품 선택 소제목은 제품명으로 갑자기 시작하지 않고 `욕실에서 이 관리를 편하게 이어가려면?`, `식사 준비 시간을 줄이려면 무엇을 확인할까요?`처럼 앞의 생활 행동을 이어받는다. 제품명은 소제목 아래 본문에서 필요 이유와 함께 처음 제시한다.
- 실제 생활에서 독자가 겪을 법한 장면을 한 번은 넣어 설명한다. 다만 직접 사용하거나 겪은 것처럼 꾸미는 가짜 후기는 쓰지 않는다.
- 제품이 주제의 행동과 자연스럽게 연결될 때만 질문형 소제목 하나를 제품 선택 기준에 사용한다. 소제목 전에는 제품명 없이 남은 생활 불편과 집에 있는 도구로 가능한 방법을 설명하고, 생활 질문형 소제목 아래에서 제품을 처음 소개한 뒤 크기·구조·사용 편의·관리 방법처럼 실제 비교할 기준 4~6개를 제시한다. 제품 연결이 억지스러우면 별도 제품 소제목을 만들지 않는다.
- 제품 구간은 해결 방법 바로 뒤, 진료·응급 신호보다 앞에 둔다. 진료 기준 뒤에는 새 제품 설명을 시작하지 않으며 글의 마지막 정보 구간은 진료 기준으로 마무리한다.
- 실제 상품 상세정보가 없으면 제품 카테고리의 일반적인 선택 기준만 쓴다. 실제 상품이 있으면 제공된 상세정보로 확인되는 특징만 선택 기준과 CTA에 연결하고, 확인되지 않은 기능·소재·효과를 만들지 않는다.
- 사용자가 특정 제휴상품을 지정해도 `지정 상품`, `사용자가 고른 상품`이라고 독자에게 말하거나 글 앞부분부터 상품명을 반복하지 않는다. 음식·생활관리로 이어지는 필요성이 생긴 뒤 상품명을 처음 소개한다. 마지막 행동 문단에서는 실제 표시사항·구성·식사 또는 사용 환경을 비교한 뒤 조건이 맞으면 구매를 결정하도록 이어 가고, 다음 별도 문단에는 `이럴 때 살펴볼 제품: **제품명**` 한 줄만 둔다. 상품을 지정하지 않은 자동 추천 모드는 기존처럼 `제품 후보: **제품명**`만 둔다.
- 추천 제품은 글의 핵심 생활 장면에서 독자가 실제로 사용할 수 있는 비처방 상품군으로 고른다. 식품이나 건강기능식품을 우선하지 않고 생활용품·주방도구·운동용품·수면환경용품·위생용품·보관용품과 일반 식품을 동등하게 비교한다. 기록 노트·건강 수첩·증상 일지·다이어리는 제품 후보와 제품 선택 소제목에서 제외한다. 증상 기록이 꼭 필요하면 휴대전화 메모처럼 별도 구매가 필요 없는 방법을 본문에서 짧게 안내한다. 예: 음료 온도 조절→디지털 음료 온도계, 식단 준비→전자 주방저울·밀폐 소분용기, 수면 환경→차광 수면안대, 걷기·근력운동→스트레칭 밴드·폼롤러·스텝퍼, 장 건강 식사→무가당 플레인 요거트 또는 소분용기, 혈변·치질 생활관리→변기 설치형 좌욕기, 자세 관리→허리 쿠션, 아이 음식 알레르기 전달→방수 식품 알레르기 표시 스티커.
- 처방약·일반의약품·치료 효과를 내세운 제품은 추천하지 않는다. 혈압계·알코올 측정기처럼 판단에 영향을 줄 수 있는 도구는 의료진 안내·법적 안전 기준을 대신하지 않는다고 함께 밝힌다.
- 해시태그 정확히 6개는 글의 맨 아래에 둔다. 원고 JSON과 최종 발행 본문에는 출처 목록과 URL을 넣지 않으며, 참고자료는 사실 확인용 내부 기록으로만 보관한다.
- 티스토리에 저장할 때 상단에 `목차`를 자동으로 만들고 모든 `heading` 소제목을 번호가 붙은 H2로 입력한다. 원고에는 번호와 목차를 중복해서 쓰지 않는다.

## 원고 생성과 빠른 확인

- 건강 원고는 AI로 한 번만 작성한다. 별도의 AI 자체 검수나 두 번째 전체 재작성 호출을 하지 않는다.
- 작성 뒤에는 코드로 빠르게 확인할 수 있는 필수 항목만 검사한다: 정상적인 제목·본문, 이미지 자리 4~6개, 해시태그 6개, 제휴 추천에 의약품·복용 유도 표현이 없는지.
- 분량·질문형 소제목·요약·CTA 같은 글쓰기 기준은 첫 작성 지침으로 유지하되, 이 권장 기준 때문에 원고 전체를 다시 생성하거나 작업을 중단하지 않는다.
- 첫 결과를 내기 전에 같은 증상 설명·생활관리·진료 권고·제품 필요성·결론이 반복되는지 한 번 확인해 합친다. 이 과정은 별도 AI 재작성 호출을 만들지 않는다.
- 필수 형식 또는 건강 안전 항목에 문제가 있을 때만 저장을 중단하고 해당 문제를 알린다.

## 이미지 자리

본문에 4~6개의 `image` 블록을 넣는다. 각 블록에는 순서(`slot`), 짧은 위치 제목(`caption`), 구체적인 장면 설명(`desc`)을 둔다. 대표 장면, 생활 문제 장면, 주제에 필요한 확인 장면, 실천 장면이 겹치지 않게 구성한다. 기록 장면은 기록이 실제 판단에 필요한 글에서만 사용한다.

## 대표이미지

- 본문 이미지 4~6장과 별도로 대표이미지 1장을 추가한다.
- 대표이미지는 항상 `1080×1080px` 정사각형, 화면 비율 `1:1`로 만든다.
- 대표이미지는 글 제목의 핵심 검색어를 큰 글자로 넣고, 독자가 얻을 내용을 나타내는 관련 문구를 짧게 덧붙인다.
- 대표이미지 배경과 오버레이는 따뜻한 오렌지·앰버 그라데이션을 약하게 사용해 원본 사진이 충분히 보이게 한다. 진한 초록이나 청록이 대표 색상으로 보이지 않게 한다.
- 핵심 키워드는 1개만 사용한다. 관련 문구는 한 줄 또는 두 줄, 8~18자 정도로 쓰고 과장·공포·치료 보장·구매 유도 표현을 피한다.
- 예: 핵심 키워드 `혈당스파이크`, 관련 문구 `오전 허기 줄이는 아침 식사 기준`.
- 한글이 깨지는 것을 막기 위해 이미지 생성 모델에 문구 렌더링을 맡기지 않는다. 먼저 문구가 들어갈 여백이 있는 관련 배경을 생성한 뒤, 로컬 이미지 편집으로 확정된 한글 문구를 정확히 입힌다.
- 대표이미지만 글자를 허용한다. 본문 이미지는 계속 텍스트·로고·워터마크 없이 생성한다.
- 파일명은 `00-대표이미지-핵심키워드.png`로 저장한다. 본문 이미지 파일 번호는 `01`부터 시작한다.

## 실행 순서

Codex가 글감 선택부터 직접 진행할 때는 글 하나를 아래 순서로 모두 끝낸 뒤에만 다음 글로 넘어간다.

1. 건강 글감 하나를 고르고 공식 자료를 조사한다.
2. 글과 이미지 자리 4~6개를 작성한다.
3. 티스토리에 **1차 비공개 저장**한다. 이 단계에서는 공개하지 않는다.
4. 비공개 저장 성공과 제목을 확인한다.
5. 글의 핵심 키워드와 관련 문구를 정하고, 문구가 정확히 들어간 대표이미지 1장을 만든다.
6. 이미지 자리 순서에 맞는 본문 이미지 4~6장을 생성한다. 본문 이미지에는 텍스트·로고·워터마크·약품 포장·의료 진단 장면을 넣지 않는다.
7. 이미지를 `C:\Users\이승아\Downloads\건강블로그이미지\YYYY-MM-DD-글제목\`에 `00-대표이미지-핵심키워드.png`, `01-본문장면.png` 순서로 저장한다.
8. 대표이미지를 포함해 파일이 실제로 5~7장 존재하는지 확인한다.
9. 방금 1차 비공개 저장한 글을 다시 연다. 제목이 일치하지 않으면 본문을 지우지 말고 중단한다.
10. `이미지 N 넣을 자리`와 `추천 장면:` 안내를 제거한다. 대표이미지는 글 맨 위에, 본문 이미지는 `slot` 순서에 맞는 위치에 넣는다.
11. 티스토리 편집기에서 대표이미지 1장과 본문 이미지 4~6장이 모두 보이고 안내 문구가 남지 않았는지 확인한 뒤 선택한 모드에 따라 **비공개 저장 또는 공개 발행**한다.
12. 같은 글을 다시 열어 이미지 수와 안내 문구 제거를 재확인한다. 새 글을 하나 더 만들지 않고 기존 1차 비공개 글을 갱신한다.

여기까지가 완료 기준이다. 제목 확인, 이미지 전체 배치, 안내 문구 제거, 최종 저장 확인 중 하나라도 실패하면 1차 비공개 글과 로컬 이미지는 그대로 보존하고 실패한 배치 단계만 재시도한다.

## 이미지 생성·배치 완료 규칙

- 1차 비공개 저장 뒤 `imageCount: 0` 또는 `imagesPending: true`인 글은 아직 완료가 아니다.
- Codex는 사용자가 따로 “이미지를 만들어”라고 다시 말하지 않아도, 같은 글의 대표이미지 1장과 본문 이미지 4~6장을 바로 생성하고 저장한다.
- **1차 비공개 저장은 작업 종료 지점이 아니다.** 저장 성공을 확인한 즉시 같은 작업 안에서 이미지 생성·로컬 저장·티스토리 배치·최종 저장을 연속 실행한다. 어느 단계라도 남아 있으면 사용자에게 완료 답변을 보내거나 다음 요청을 기다리지 않는다.
- 글 하나를 처리하는 동안 그 글의 제목과 이미지 자리 정보를 작업 대상으로 고정한다. 이미지 저장과 상태 갱신이 끝나기 전에는 다른 글을 시작하지 않는다.
- 생성에는 Codex 기본 이미지 생성 기능을 사용한다. API 키를 요구하거나 ZIP 파일을 만들지 않는다.
- 파일은 글마다 별도 폴더에 저장한다. 대표이미지는 `00-...png`, 본문 이미지는 `01-...png`부터 이미지 자리 `slot` 순서와 동일하게 이름을 붙인다.
- `imageSlotCount`는 본문 이미지 자리 수 4~6개를 뜻하고, `imageCount`는 대표이미지를 포함한 실제 저장 파일 수 5~7개로 기록한다.
- 저장 뒤 파일 개수와 파일 크기를 확인하고, 작업 데이터의 `imageCount`, `imagesPending: false`, `imageDownloadDir`을 갱신한다.
- 티스토리 배치가 끝나면 `imagePlacementCompleted: true`, `insertedImageCount: imageCount`를 기록한다. 비공개 저장 모드일 때는 `secondDraftSaved: true`도 기록한다.
- 완료 보고에는 반드시 글 제목, 실제 저장 폴더 링크, 생성·배치한 이미지 장수, 티스토리 최종 저장 결과를 포함한다. 이미지 생성·저장·배치 확인 전에는 완료라고 보고하지 않는다.
- 여러 글을 요청받아도 한 글의 `글 작성 → 1차 비공개 저장 → 이미지 생성·로컬 저장 → 같은 글에 배치 → 최종 저장/발행`을 끝낸 다음 다음 글로 넘어간다.

### 완료 직전 필수 검사

아래 여섯 조건이 모두 참일 때만 글 1개를 완료로 보고한다.

1. 티스토리 1차 비공개 저장이 성공했다.
2. `imageSlotCount`가 4~6이고, `imageCount`가 `imageSlotCount + 1`이며, `imagesPending`이 `false`다.
3. `imageDownloadDir`의 실제 이미지 파일 수가 `imageCount`와 같고 모든 파일 크기가 0보다 크다.
4. 대표이미지 파일명이 `00`부터 시작하고 `1080×1080px` 정사각형이며 핵심 키워드·관련 문구가 정확히 보인다. 본문 이미지 파일명은 `01`부터 시작해 이미지 자리 순서와 일치한다.
5. 같은 1차 비공개 글을 다시 열어 대표이미지는 맨 위, 본문 이미지는 각 `slot` 위치에 배치했고 `insertedImageCount`가 `imageCount`와 같다.
6. 이미지 자리·추천 장면 문구가 남아 있지 않고 `imagePlacementCompleted: true`이며 최종 저장 결과 재확인까지 통과했다.

하나라도 거짓이면 완료 보고 대신 누락된 이미지 생성·복사·상태 갱신부터 계속한다.
