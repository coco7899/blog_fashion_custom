# 03-health-affiliate-blog

## 목표

독자의 생활 속 불편에서 출발해 확인할 기준과 오늘 할 수 있는 행동을 알려 주는 건강 글을 작성한다. 질병을 단정하거나 치료·약 복용·구매를 유도하지 않는다.

## 글쓰기 기준

- 공식 기관·의료기관·학회 자료를 우선 확인하고, 기사 문장을 복사하지 않는다.
- 제목은 `증상 또는 생활 고민 + 자연스러운 질문 + 확인 기준`으로 쓴다.
- 본문은 1,500~2,200자, 문단은 1~3문장으로 쓴다.
- 첫 2~4문장 안에 독자의 질문에 직접 답하고, 생활에서 확인할 기준·예외·진료가 필요한 신호를 설명한다.
- 서론 바로 뒤에는 `이 글에서 확인할 핵심 N가지`를 굵게 쓰고 번호 목록으로 3~5줄 요약한다. 제목에 숫자가 있으면 같은 숫자와 판단 기준을 그대로 사용한다.
- 약을 줄이거나 중단하라고 말하지 않는다. 증상만으로 진단하지 않으며, 응급 신호는 진료 필요성을 분명히 쓴다.
- 마지막 CTA는 오늘 할 행동을 제안하는 2~3문장으로 쓴다. 구매를 강요하지 않는다.
- 오늘 할 행동에는 주제에 맞는 음식·식사 구성·생활습관·가벼운 운동을 먼저 넣는다. 제품은 이 실천을 더 편하게 이어 가는 보조 수단으로만 자연스럽게 연결한다.
- CTA 아래 두 줄을 비운 뒤 `이 글에 제휴하면 좋은 제품: **제품명**`을 한 줄로 추천한다. 이는 사용자의 최종 제휴 판단을 위한 추천일 뿐, 링크·가격·후기·구매 유도 문구는 넣지 않는다.
- 추천 제품은 글의 핵심 생활 장면에서 실제로 쓰는 비처방 상품군으로 고른다. 기록 노트·물병처럼 같은 제품을 반복 추천하지 않는다. 예: 수분 관리→대용량 물병, 식단 점검→전자 주방저울·밀폐 소분용기, 수면 환경→차광 수면안대, 장 건강 식사→무가당 플레인 요거트, 자세 관리→허리 쿠션.
- 처방약·일반의약품·치료 효과를 내세운 제품은 추천하지 않는다. 혈압계·알코올 측정기처럼 판단에 영향을 줄 수 있는 도구는 의료진 안내·법적 안전 기준을 대신하지 않는다고 함께 밝힌다.
- 해시태그 정확히 6개는 글의 맨 아래에 둔다. 출처 목록과 URL은 본문·이미지 캡션·네이버 글에 넣지 않고 조사 근거로만 보관한다.

## 이미지 자리

본문에 4~6개의 `image` 블록을 넣는다. 각 블록에는 순서(`slot`), 짧은 위치 제목(`caption`), 구체적인 장면 설명(`desc`)을 둔다. 대표 장면, 생활 문제 장면, 확인·기록 장면, 실천 장면이 겹치지 않게 구성한다.

## 실행 순서

Codex가 글감 선택부터 직접 진행할 때는 글 하나를 아래 순서로 모두 끝낸 뒤에만 다음 글로 넘어간다.

1. 건강 글감 하나를 고르고 공식 자료를 조사한다.
2. 글과 이미지 자리 4~6개를 작성한다.
3. 네이버 블로그에 **1차 임시저장**한다. 발행하지 않는다.
4. 임시저장 성공과 제목을 확인한다.
5. 이미지 자리 순서에 맞는 이미지 4~6장을 생성한다. 텍스트·로고·워터마크·약품 포장·의료 진단 장면은 피한다.
6. 이미지를 `C:\Users\이승아\Downloads\건강블로그이미지\YYYY-MM-DD-글제목\`에 `01-대표장면.png`부터 순서대로 저장한다.
7. 파일이 실제로 4장 이상 존재하는지 확인하고, 사용자에게 제목·폴더 경로·파일 순서·각 파일을 넣을 본문 위치를 알려 준다.

여기까지가 완료 기준이다. **네이버 임시글을 다시 열어 이미지를 자동 배치하거나 2차 임시저장을 시도하지 않는다.** 사용자가 사진을 직접 넣은 뒤, 안내 문구를 지우고 필요하면 발행한다.

## 이미지 생성 완료 규칙

- 1차 임시저장 뒤 `imageCount: 0` 또는 `imagesPending: true`인 글은 아직 완료가 아니다.
- Codex는 사용자가 따로 “이미지를 만들어”라고 다시 말하지 않아도, 같은 글의 이미지 4~6장을 바로 생성하고 저장한다.
- 생성에는 Codex 기본 이미지 생성 기능을 사용한다. API 키를 요구하거나 ZIP 파일을 만들지 않는다.
- 파일은 글마다 별도 폴더에 저장하고, `01-...png`부터 이미지 자리 `slot` 순서와 동일하게 이름을 붙인다.
- 저장 뒤 파일 개수와 파일 크기를 확인하고, 작업 데이터의 `imageCount`, `imagesPending: false`, `imageDownloadDir`을 갱신한다.
- 완료 보고에는 반드시 글 제목, 실제 저장 폴더 링크, 생성한 이미지 장수를 포함한다. 이미지 생성이나 저장 확인 전에는 완료라고 보고하지 않는다.
- 여러 글을 요청받아도 한 글의 `글 작성 → 1차 임시저장 → 이미지 생성·저장·검증`을 끝낸 다음 다음 글로 넘어간다.

## 최종 확인

1. 건강 안전 수칙을 지켰는가?
2. 질문형 소제목이 3개 이상인가?
3. CTA·제품 추천·해시태그의 순서가 맞는가?
4. 이미지 자리가 4~6개인가?
5. 네이버 1차 임시저장이 확인됐는가?
6. 다운로드 폴더에 이미지가 4장 이상 저장됐는가?
7. 자동 이미지 재배치나 2차 임시저장을 완료로 표시하지 않았는가?
